# AGENTS.md

Read this first if you are a coding agent asked to add an on-device LLM to an Android app with this SDK.

1. `README.md` is the integration guide: the Gradle lines, the five-line call, the ids that work today, and what the SDK does that hand-rolled code usually does not. The dependency is `io.github.john-rocky.hfmodels:hfmodels-litertlm:0.1.2` (Maven group with a hyphen; Kotlin package `io.github.johnrocky.hfmodels` without). Inside this repository the runtime pins are `gradle.properties` and the verified combinations `tested-runtime-matrix.json`; never quote a version from memory.
2. `docs/api.md` is the complete public surface with imports and signatures, including the runtime types an app touches (`Contents`, `Content`, `ConversationConfig`, `Message`). Read it instead of unzipping the sources jar or running `javap`.
3. `skills/hfmodels-android/SKILL.md` is the step-by-step procedure with the three finish conditions. Follow it in order; do not skip the device check.
4. `docs/errors.md` maps every `ModelException.code` to the fix. When a load fails, read the code, not the stack trace.
5. `catalog/entries/*.json` are the model ids the bundled catalog resolves without any change to the model repo; `core/src/main/assets/hfmodels/catalog.json` is what the AAR ships. A model with `hfmodels.json` in its own repo needs no catalog entry. Thinking models (Qwen3, DeepSeek-R1-Distill, `*-Thinking`): on 0.1.0 not supported, say so rather than forcing one; from 0.1.1 their reasoning arrives in `Message.channels["thought"]` and `m.text` is the answer (`docs/api.md`, "Thinking models").
6. `tested-runtime-matrix.json` says which runtime versions were verified on which device, with the log paths. Do not present a version that is not in it as verified.
7. Model files are never in this repository and never in an APK. The SDK downloads them into the app's private files dir and verifies the sha256 before loading.
8. A cancelled `ChatSession` is INVALID; the next turn needs `createConversation()` again. Cancelling the collecting coroutine stops the model. `closeAndJoin()` before the process goes away. On a model whose layers keep a running state (linear attention / SSM; verified on decider-2b-vision) a new conversation on the same loaded model is NOT a fresh state under LiteRT-LM 0.16.1 to 0.17.1 (google-ai-edge/LiteRT-LM#3165): for one request after another keep one conversation and add turns, or load the model again; `samples/pong/README.md` has the measurement.
9. Numbers here are measurements on named devices with dates; do not extrapolate them to other devices.
10. The device check is a file, not a UI procedure: `samples/chat/src/androidTest/kotlin/io/github/johnrocky/hfmodels/check/ChatDeviceCheck.kt` copied into the app's `androidTest` proves load, answer, Stop and release on the connected phone and prints `RESULT` lines under `adb logcat -s hfmodels-check` (0.1.1 or newer).
11. Typed decisions (0.1.2, module `hfmodels-litert`; the app also needs `android.uniquePackageNames=false`): `EncoderDecisions` is the task, `TypedDecisions.decide(state, questions)` the call, `Question` / `Answer` the `/v1/systemone` request and answer forms; the section "Typed decisions" of `docs/api.md` is the whole surface. The models are `litert-community/laya-LiteRT` (its repo carries `hfmodels.json`; `ModelRef("litert-community/laya-LiteRT", variant = …)`; `samples/decide/README.md` says which variant for which language and backend) and, from 0.1.3, `litert-community/Julia-1-LiteRT` (its repo carries `hfmodels.json` from commit 8f36857c and the bundled catalog pins the same descriptor at b92a0d21; `ModelRef("litert-community/Julia-1-LiteRT", variant = "s512_fp32" | "s1024_fp32")`, multilingual, 2 to 20 options per question, GPU FP32 or CPU only). Also from 0.1.3, English, GPU FP32 or CPU (GLiNER2.5-Decide also on the NPU with `s128_npu_wfp16`, Open-Decision with `s256_npu_wfp16`); each repo carries `hfmodels.json` (from the commit named here) and the bundled catalog pins the same descriptor at a commit whose own `hfmodels.json` is the same or absent (the SDK reads a commit's own file before the catalog; `tools/check_catalog_pins.py` checks every entry): `litert-community/GLiNER2.5-Decide-LiteRT` (`hfmodels.json` from f6f6e9c9, catalog at f6f6e9c9; `s128_wfp16` | `s256_wfp16` | `s512_wfp16` | `s128_npu_wfp16`, the last one the s128 graph changed for float16 hardware: NPU opt-in with `BackendPolicy.Require(BackendKind.NPU)`, its `gpu` profile in FP16 with FP32 accumulation; at most 32 labels), `litert-community/GLiClass-Edge-v3.0-LiteRT` (`hfmodels.json` from b6ec1f75, catalog at 88c90950, the commit before; `s128_fp32` | `s256_fp32`, at most 25 labels) and `litert-community/Open-Decision-DeBERTa-v3-Large-LiteRT` (`hfmodels.json` from 6ebf0946, catalog at 26a2b642, the commit that added `s256_npu_wfp16` with its `hfmodels.json`; `s256_wfp16` | `s512_wfp16` | `s256_npu_wfp16`, the last one the S256 graph changed for float16 hardware: NPU opt-in with `BackendPolicy.Require(BackendKind.NPU)`, its `gpu` profile in FP16 with FP32 accumulation; a request's questions in one forward); on these three a choice's description, not its key, is the string the model reads and the key comes back as the answer, and a request longer than the window is refused with `CONTEXT_LIMIT_EXCEEDED` (Open-Decision first cuts the state to 256 tokens). `samples/promises` is a one-screen app on GLiNER2.5-Decide with a device check (its README says what it showed). The families render options differently and decode differently (`docs/api.md`, "Families"); the SDK does that per family, an app writes the same `Question`s. The measured numbers are in the README tables and `tested-runtime-matrix.json` (`typed_decisions`, `typed_decisions_julia1`, `typed_decisions_gliner2_decide`, `typed_decisions_gliner2_decide_npu`, `typed_decisions_gliclass`, `typed_decisions_deberta_decision`, `typed_decisions_deberta_decision_npu`), one device, one day. Language-model bundles are not a decision backend in this release (the LiteRT-LM Kotlin API has no scoring call); use `Tasks.Chat` for them. The NPU (Qualcomm HTP, 0.1.3) is opt-in: the app packages Qualcomm's runtime (`tools/fetch_npu_libs.sh`) and loads with `BackendPolicy.Require(BackendKind.NPU)`; `docs/api.md`, "NPU".
12. Voice (main, 0.2.0, not on Maven Central yet; module `hfmodels-voice`, which brings `hfmodels-litert` and `hfmodels-litertlm`, so the app also needs `android.uniquePackageNames=false`): `VoiceLoop(transcriber, chat, speaker, PhoneTools.all(context), VoiceLoopConfig(player = SpeechPlayer()))` hears (`Transcribe`, Zipformer CTC), acts with tool calls on `Tasks.Chat` and answers aloud (`Speak`, KittenTTS), one `HfModels` per model; the section "Voice" of `docs/api.md` is the whole surface and `samples/voice` the app. The two speech repos carry `hfmodels.json` (Zipformer from commit fa063a88, Kitten from 2c5b198f, its four G2P files with it) and the bundled catalog pins those commits, so `ModelRef("litert-community/Zipformer-medium-CR-CTC-LiteRT")` and `ModelRef("litert-community/kitten-tts-nano-0.8")` load them by id; what ran at those commits, on one Galaxy S26 on 2026-10-05 and with the files already on the phone: the loads by id (online, then offline through the binding), the transcribe and speak gates pinned at those commits (all passed) and a `samples/voice` turn that asked the time (answered aloud); the files' download from the Hub ran on a Mac's JVM, not on a phone; `VoiceDeviceCheck` and the alarm, timer and calendar tools have not run at those commits, and the README "Voice" tables are earlier runs with development descriptors at the commits before, so tell the user which of these ran rather than presenting the voice loop as verified at those commits; prove an integration with `samples/voice/src/androidTest/kotlin/io/github/johnrocky/hfmodels/check/VoiceDeviceCheck.kt` (screen on and the app visible: Android drops the Clock app's start from an app it cannot see; no alarm at or before the check's 07:30 in the Clock app, or it stops with `RESULT step=precondition ok=false`); the README "Voice" tables are one Galaxy S26, synthetic voices, one day.
