# Cutting an SDK release

1. `HfModelsVersion.SDK_VERSION` in `core/src/main/kotlin/io/github/johnrocky/hfmodels/Api.kt` = the release version (it is what `PreparedModelInfo.sdkVersion` reports; 0.1.0 shipped reporting `0.1.0-SNAPSHOT`).
2. The same version in the Gradle lines of `README.md`, `AGENTS.md`, `llms.txt`, `docs/api.md`, `skills/hfmodels-android/SKILL.md` and `skills/typed-decisions-on-device/SKILL.md`; in the default `?: "<version>"` of `coordinates(…)` in `core`, `litertlm`, `litert` and `voice/build.gradle.kts` (what a publish without `-PhfmodelsVersion` gets); in the local-publish comments `-PhfmodelsVersion=<version>-local` of `core` and `litertlm/build.gradle.kts`; and in the commented Gradle line of the seven samples' `build.gradle.kts` (`ask`, `chat`, `decide`, `finder`, `pong`, `promises`, `voice`). Text in those files and in `docs/errors.md` that calls something main only, a SNAPSHOT or not on Maven Central yet becomes the released version (`git grep -n -E 'SNAPSHOT|not on Maven Central|not released|[Mm]ain only'`); the SDK version a recorded run used stays as recorded.
3. `./gradlew :core:testDebugUnitTest :litertlm:testDebugUnitTest :litert:testDebugUnitTest :voice:testDebugUnitTest` (the `voice` tests that load LiteRT-LM's classes need a JDK 21 test JVM, `-Dorg.gradle.java.home=<JDK 21>`: LiteRT-LM 0.16.1's class files are Java 21, and on an older JDK they are skipped) and the device tests (`litertlm/src/androidTest`, `tools/gate.sh` on the bundled catalog; the decision gate `tools/decide_gate.sh` with each family's `GATE_TEST`; the voice gates `tools/transcribe_gate.sh`, `tools/speak_gate.sh`, `tools/tools_gate.sh`, `tools/voiceloop_gate.sh` and `samples/voice`'s `VoiceDeviceCheck`) on the runtime pinned in `gradle.properties`; a new runtime pin needs a new row in `tested-runtime-matrix.json` with its log.
4. `tools/check_catalog_pins.py` exits 0: every catalog entry pins a commit that carries no `hfmodels.json` or one the SDK reads the same (at one commit the SDK reads the repo's own file before the catalog, so an entry behind an older file is never read online).
5. `HfModelsVersion.SDK_VERSION` inside the AAR is the version about to be published: `./gradlew publishAllPublicationsToLocalRepository -PhfmodelsVersion=<version>` writes the four artifacts into `local-maven/`, and `javap -constants` on `io.github.johnrocky.hfmodels.HfModelsVersion` in the `classes.jar` of `hfmodels-core-<version>.aar` prints it (`-PhfmodelsVersion` sets the coordinates, not this constant).
6. `./gradlew publishAndReleaseToMavenCentral -PhfmodelsVersion=<version>` (credentials and the signing key come from `~/.gradle/gradle.properties`, never from the repository).
7. Tag `v<version>` only after `https://repo1.maven.org/maven2/io/github/john-rocky/hfmodels/<artifact>/<version>/` answers 200 for each of the four artifacts: `hfmodels-core`, `hfmodels-litertlm`, `hfmodels-litert` and `hfmodels-voice`.
8. Set `SDK_VERSION` to `<next>-SNAPSHOT`.
